# Slicer-side and practitioner tools/workflows for turning textured 3D models (Tripo/Meshy/Hunyuan3D/TRELLIS GLB/OBJ) into multi-colour prints (Bambu AMS / Prusa MMU / multi-toolhead) — state as of Nov 2026

Research date: 2026-11-17. Sources were opened directly unless marked "(search snippet only, not opened)". Note on access: Reddit (reddit.com and mirrors) could not be fetched from this environment, and the GitHub REST API refused per-issue reads for bambulab/BambuStudio. GitHub issue *search* results and GitHub web pages fetched through WebFetch worked. Bambu Lab wiki and forum pages were read in full through curl (wiki HTML, Discourse JSON).

## 1. Bambu Studio and OrcaSlicer: colour import (OBJ/MTL, 3MF colorgroup/basematerials, "Standard 3MF Color Parsing", texture/UV import, auto-quantisation, max colours, version history, GitHub issues/PRs)

### Takeaway
Since 2.7.1 (public release around May 2026), Bambu Studio has a native **Texture to Color Painting** importer. It takes textured OBJ/glTF/GLB/FBX, clusters the texture into 1–32 colours (with Auto, Boundary Smoothness 0–10 and Gap Area 0–5 % controls), writes the result as slicer colour painting, and maps the colours to filaments, CMYKW colour-mixing filaments included. It sits beside the older OBJ vertex/MTL colour import (2024) and the 2.5 "Standard 3MF Color Parsing" dialog (vertex/face colour in 3MF, up to 32 colours, no textures). OrcaSlicer 2.5.0 (alpha, then beta on 27 Oct 2026) added a matching unified "Import Model" dialog for textures, vertex colours and OBJ material colours, and dropped its old OBJ colour dialog. In practice these slicer features can now stand in for the "quantise texture → paint_color 3MF" stage of a custom pipeline. They cannot stand in for semantic or part-aware colouring or for removing baked-in shading.

### Cited Findings

**Bambu Studio: Texture to Color Painting (2.7.x)**
- Official wiki: "Texture to Color Painting imports a model with a texture map into Bambu Studio and converts it into a multi-color model… You can model it yourself, generate it with AI, or download a textured model…" Requires **Bambu Studio 2.7.1 or later** ("Texture to Color Painting was added in Bambu Studio 2.7.1"). — [Bambu wiki: Texture to Color Painting](https://wiki.bambulab.com/en/software/bambu-studio/texture-to-color)
- Supported formats: **OBJ, glTF, GLB, FBX (a texture map is required)**. Limitations: "Converting several textured models at the same time is not supported yet. Import them one by one." and "**Draco-compressed glTF / GLB is not supported yet.**" The settings window opens automatically after a textured model is imported. — [Bambu wiki: Texture to Color Painting](https://wiki.bambulab.com/en/software/bambu-studio/texture-to-color)
- Step 1 "Simplify Colors". **Color Count**: "A model with a texture map usually contains thousands of colors… This parameter clusters those colors and maps them to a limited set… this feature supports **up to 32 colors**. Range: 1–32", with 4/8/16 quick buttons and an **Auto** button that "determines the best Color Count and recalculates the filament mapping." **Boundary Smoothness** (0–10): "A lower value keeps the boundary sharper. A higher value makes the edge softer." **Gap Area (%)** (0–5): "controls the extent to which small color regions are merged into neighboring regions." — [Bambu wiki: Texture to Color Painting](https://wiki.bambulab.com/en/software/bambu-studio/texture-to-color)
- Step 2 "Filament Matching" offers four methods: (1) "Use official mixing kits" (PLA Palette CMYKW); (2) check "Color mixing" to blend the filaments already loaded; (3) "Complete All Filaments", which creates single-colour filaments matching each cluster; (4) manual dropdown per colour, plus a configurable "filament match color difference threshold". — [Bambu wiki: Texture to Color Painting](https://wiki.bambulab.com/en/software/bambu-studio/texture-to-color)
- 2.7.1 release note: "2.7.1 Public Release is a new version based on 2.6.1 Public Beta and 2.7.0 Public Beta… introduces important new features such as **Texture‑to‑Color Painting** and the Filament Manager". It also lists "Texture‑to‑Color Painting Feature Optimization: … fixes to UV mapping for multi‑texture atlases, improved base‑color material processing logic, and optimized color‑clustering algorithm and smoothing control", "New mesh error detection and repair confirmation workflow… ensure model watertightness, and can invoke the Windows mesh‑repair tool", "FBX file import support", and "**Painted color information is now preserved after a Plane Cut**… Minor alignment differences may appear on painted facets near the cut surface." Also: "Changed the default Paint Fill mode to Edge Detection mode." — [Bambu Studio 2.7.1 release note](https://wiki.bambulab.com/en/software/bambu-studio/release/release-note-2-7-1)
- Third-party coverage says the feature first shipped in the 2.7.0 *beta* and that multi-texture objects were still weak at that point ("works best with individually textured models"). — [3Druck: Bambu Studio 2.7 Beta brings texture-to-color conversion](https://3druck.com/en/programs/bambu-studio-2-7-beta-brings-texture-to-color-conversion-and-improved-mesh-diagnostic-tool-28157353/) (search snippet only, not opened); [bambuhub.net article](https://bambuhub.net/articles/bambu-studio-2-7) dates 2.7.1 Stable to the "May 2026 release notes" (search snippet only; 403 on fetch)
- User friction with the new import dialog (Bambu Studio **2.8.2.60**, Aug 2026). One user has to "slide smooth level to zero… hit apply then fix the materials that keeps trying to add PLA matches" on every OBJ import, wants "default check boxes. default to zero smoothing and default to loaded materials", and complains it "sometimes tries to mix colors… instead of just matching to the red and gray petg I have loaded". He later downgraded to 2.7.1.62. Another user explains: "When there are true RGB colors attached to faces in the model… it tries to map them into mixed filament colors. It can create up to 32 colors if needed." — [Bambu forum: "Importing is a mess" (Aug 2026)](https://forum.bambulab.com/t/importing-is-a-mess/258389)
- Colour mapping is only offered at import: "there's no way to bring up the mapping dialog again, at least not w/out re-importing"; workaround is right-click → "Reload from disk". — [Bambu forum: "Why does studio only let us map colors on import?" (Aug 2026)](https://forum.bambulab.com/t/why-does-studio-only-let-us-map-colors-on-import/258461)

**Bambu Studio: Color Mixing (2.5.3+), relevant to how texture colours get mapped**
- Color Mixing needs **Bambu Studio v2.5.3+**; the Gradient Color Curve needs v2.7.1+. It "works by splitting each base layer… into 2–3 thinner sublayers and printing each sublayer with a different filament." Only filaments of the same type can be mixed. The colour-prediction method "is based on @ratdoux's approach in OrcaSlicer-FullSpectrum, updated and integrated by the Bambu Studio team in **v2.6.1**." — [Bambu wiki: Color Mixing](https://wiki.bambulab.com/en/bambu-studio/color-mixing)
- Texture to Color Painting can feed straight into colour mixing: "During filament matching, the painted colors can be broken down into a base-color set, such as CMYKW." — [Bambu wiki: Color Mixing](https://wiki.bambulab.com/en/bambu-studio/color-mixing)

**Bambu Studio: Standard 3MF Color Parsing (2.5+)**
- "Currently, the software supports **Vertex Coloring and Face Coloring**, but does **not yet support Texture Mapping**" in 3MF. After a standard 3MF with colour data is imported, a "Standard 3MF Color Parsing" window opens: "Set the specified number of model colors (**supports up to 32 colors**; if the model exceeds 32 colors, the software automatically identifies and prioritizes the top 32 most frequently used colors)". It shows a system-recommended colour count, before/after thumbnails, clustered colours auto-matched to the loaded filament with the smallest colour difference, and quick options **Append / Color match / Reset**. — [Bambu wiki: Standard 3MF File Color Parsing](https://wiki.bambulab.com/en/bambu-studio/Standard-3MF-File-Color-Parsing)
- Date context: a Feb 2026 forum post says the 3MF colour import "is new in Studio v2.5". In 2.4, object colours in a 3MF were "preserved, there's just no UI for assigning colors… assigns colors/filaments to objects sequentially". The same post shows a Fusion 3MF using `<m:colorgroup>` plus an object-level `pid`/`pindex`. A SolidWorks user (Aug 2026, Studio 2.7.1.62) reports that a 3MF with "Include appearances" carries body/face/feature colour into Studio and "give[s] a good translation from color to filament selection". — [Bambu forum: "Import with color" (Feb–Aug 2026)](https://forum.bambulab.com/t/import-with-color/230485)
- Complaints: on BambuStudio V2.5.0.66 "there's no way to disable that dialog right now"; it is tracked as GitHub issue #9666 ("Issues with the 'Standard 3MF Import Color' module causing incorrect color assignment"). One user says "Even when I press cancel, Bambu still pukes 10+ filaments into my workspace" (Apr 2026). Workaround: after the dialog, right-click → "Reload from disk" reloads without its effects. — [Bambu forum: "How to disable 'Standard 3mf Import color'" (Mar–Apr 2026)](https://forum.bambulab.com/t/how-to-disable-standard-3mf-import-color/241644)

**OrcaSlicer (repo now OrcaSlicer/OrcaSlicer)**
- **v2.5.0 alpha** — "Textured and coloured model import" (@SoftFever, @HanifKoh; PRs 15347, 15977, 16122): adds glTF, GLB and FBX import and can turn a textured model's colours into colour painting. Models with a texture, vertex colours or OBJ material colours open an "**Import Model**" dialog where colours are reduced to a chosen "**Color Count**", smoothed, and mapped to project filaments (new ones added as needed). It also offers a one-click "CMYW / RYBW auto-mix" or import in a single colour. It "replaces the old OBJ colour dialog". On multi-toolhead printers, OBJ colour mapping offers no more colours than there are toolheads (@Noisyfox, PR 14275). — [OrcaSlicer wiki: V2.5.0 Alpha release notes](https://www.orcaslicer.com/wiki/releases/release_2_5_0_alpha)

It also adds "**Colour from textures (Texture Displacement)**": a Colors option matches each image colour to the nearest loaded filament, with optional mixed filaments capped by "Mixed colors" (default 8). Baked colours go into colour painting, and texture layers are saved in the .3mf. — [OrcaSlicer wiki: V2.5.0 Alpha](https://www.orcaslicer.com/wiki/releases/release_2_5_0_alpha)
- **v2.5.0 beta** (released 27 Oct; year not printed, but an asset filename contains 2026-10-20): restyled Import Model dialog (PR 16768). New "**Top and bottom paint penetration layers**" (PR 16818) set "how many layers below a painted top surface, or above a painted bottom surface, take the painted color." Also translucent filament preview and an eyedropper colour picker. — [GitHub OrcaSlicer v2.5.0-beta release](https://github.com/OrcaSlicer/OrcaSlicer/releases/tag/v2.5.0-beta)

### Inferences
- For a pipeline that already writes colorgroup 3MF: opening that file in Bambu Studio ≥2.5 triggers "Standard 3MF Color Parsing", which **re-clusters** colours (max 32) and remaps them to filaments. If the pipeline has already quantised to N filament colours, expect a near 1:1 mapping, but check that the dialog does not merge or append colours. The pipeline's **paint_color** 3MF loads as native painting and skips the dialog. It remains the most deterministic route on Bambu, and PrusaSlicer 2.9.x reads it too (see §2).
- Bambu Studio 2.7.1+ / OrcaSlicer 2.5 Texture-to-Color could replace a custom texture→palette quantiser for "good-enough" results. Its controls are global (count, smoothing, small-region merge) with no semantic awareness. It cannot remove baked-in lighting/shading from AI textures, keep a dark outline out of a black filament region, or enforce per-part flat colours. Those remain the value-add of a custom pipeline.
- The Draco restriction matters: many web GLB exports are Draco-compressed. Decompressing (e.g. re-exporting through Blender/trimesh/gltf-transform) before slicer import is a cheap pre-step (inference; no source checked which AI services emit Draco).
- Because the colour mapping dialog runs only at import and cannot be reopened, iterate on palettes outside the slicer, or re-import / "Reload from disk".

## 2. PrusaSlicer: MMU painting, colour import from OBJ/3MF, texture support, ColorMix, relevant GitHub issues

### Takeaway
PrusaSlicer has strong manual MMU painting (since 2.4) and, since 2.9.6, **ColorMix** virtual extruders. It still has **no native colour import from OBJ vertex/MTL colours or textures**: #12040 has been open since Jan 2024, and #4503 (3MF basematerials ignored) since 2020. The working community route is Bambu Studio → save 3MF → open in PrusaSlicer (2.9.6 reads Bambu `paint_color`). That route **regressed in PrusaSlicer 3.0.0-alpha14** (#16268, Nov 2026).

### Cited Findings
- "Starting with PrusaSlicer 2.4, coloring an object for multi-material printing requires just a handful of bucket fills and brushstroke operations." Tools: brush (sphere/circle/triangle, optional facet splitting), Smart fill (adjustable threshold angle), Bucket fill, Height range. — [Prusa KB: Multi material painting](https://help.prusa3d.com/article/multi-material-painting_262620)
- Segmentation: painted regions on top/bottom surfaces extend inward by top/bottom solid layers; side-wall regions extend inward up to `mmu_segmented_region_max_width`. "Thin features are not printable… Such thin non-printable regions created during segmentation are thus detected and **merged with the neighboring region, changing its color**"; the article advises enabling "detect thin walls". Limits: "**The multi-material painting is limited to 16 extruders**", and it "cannot be combined with XY size compensation." — [Prusa KB: Multi material painting](https://help.prusa3d.com/article/multi-material-painting_262620)
- ColorMix: "Using any multi-color printer, it allows you to create additional color tones from the loaded filaments… the colors alternate by layers." Available "in EasyPrint and in PrusaSlicer from **version 2.9.6**". "Because the mixed colors require many tool changes, these prints produce more waste… significantly more efficient to print them using the INDX toolchanger." Mixed colours are "virtual extruders" (2- or 3-filament blends with ratio sliders). — [Prusa KB: ColorMix](https://help.prusa3d.com/article/colormix_1210432)
- #12040 "Support pre-color mapped 3D models for import" (opened 2024-01-08, still open, tagged `legacy-issue` by bot 2026-09-02, no maintainer response). Comments: UV-mapped OBJ with image colour is not supported (May 2024). Bambu added the feature in 1.9.1 (Jul 2024 comment). A user delayed buying an XL over it. Workaround (Dec 2025, agoode): "Import the color OBJ into Bambu Studio, save as 3MF, then load that file in PrusaSlicer… Bambu Studio writes PrusaSlicer-compatible 3MF data". May 2026: ColorMix makes full-colour OBJ import "more valuable". — [GitHub prusa3d/PrusaSlicer#12040](https://github.com/prusa3d/PrusaSlicer/issues/12040)
- #16268 "3.0 regression: Bambu Studio 3MF painting is no longer imported" (2026-11-10, 3.0.0-alpha14, XL 5T): 2.9.6 read Bambu `paint_color` correctly. 3.0.0-alpha14 shows "The 3MF file does not contain PrusaSlicer configuration. Only geometry was loaded." No maintainer reply yet. — [GitHub prusa3d/PrusaSlicer#16268](https://github.com/prusa3d/PrusaSlicer/issues/16268)
- Other issues found by search (titles/dates): #4503 "3MF import does not respect basematerial and related tags and attributes" (2020-07-09, open); #7314 "Feature Request: Import .Mat texture alongside .Obj file for Multi-Material Painting" (2021, closed); #10695 "Export MMU painted model to separate stls for each color" (2023, open). — [PrusaSlicer#4503](https://github.com/prusa3d/PrusaSlicer/issues/4503), [#7314](https://github.com/prusa3d/PrusaSlicer/issues/7314), [#10695](https://github.com/prusa3d/PrusaSlicer/issues/10695)
- PrusaSlicer 3.0 is still alpha. Alpha 13 brought a 0.1 mm minimum brush radius, a dedicated "Extruder Assignment" table, and 3MF unit-import fixes. — [GitHub PrusaSlicer 3.0.0-alpha13 release](https://github.com/prusa3d/PrusaSlicer/releases/tag/version_3.0.0-alpha13) (search snippet only, not opened)
- Prusa announced open-source ColorMix for EasyPrint/PrusaSlicer on 26 May 2026 (linked in a Bambu forum post). — [Bambu forum: FullSpectrum Studio thread](https://forum.bambulab.com/t/fullspectrum-studio-automatic-palette-reduction-for-hundreds-of-colors/253789)

### Inferences
- For Prusa MMU3/XL/INDX users, the user's **Bambu paint_color 3MF** is the most practical hand-off format in PrusaSlicer 2.9.x. A colorgroup 3MF or vertex-colour OBJ will load as geometry only. Pin users to 2.9.6 until #16268 is fixed. Alternatively, a pipeline could write PrusaSlicer's own `slic3rpe:mmu_segmentation` attribute (not verified here).
- PrusaSlicer's automatic "merge thin regions into neighbour" means tiny pipeline-painted details (pupils, eyebrows) may silently change colour at slice time. Check the sliced preview.

### Gaps
- Whether PrusaSlicer 3.0 plans colour/texture import was not found.
- No source checked confirms which 3MF attribute PrusaSlicer 2.9.6 reads from Bambu files (the issue only says Bambu `paint_color` was read).

## 3. Other tools: HueForge, Blender add-ons, Blender 3MF, MeshLab/Meshmixer, MakerWorld/MakerLab, web converters, standalone palette reducers

### Takeaway
HueForge is a 2D-image→layered relief ("filament painting") tool, not a figurine colouriser. For figurines, the relevant third-party tools are: the maintained Blender **3MF Import/Export** extension (Clonephaze), which claims to bake textures to discrete filament colours and keep Bambu/Orca/Prusa paint zones; the browser-based **PrintPal AMS Color OBJ Converter** (GLB/OBJ texture → painted 3MF or hard-edged vertex-colour OBJ, 2–8 colours); **FullSpectrum Studio** (palette reduction of painted Bambu 3MFs); **Meshy Multi-Color Print / MakerLab** (AI generation plus 4–16 colour 3MF); and MeshLab's "Transfer Color: Texture to Vertex" for the older OBJ-vertex-colour route.

### Cited Findings
**HueForge**
- HueForge turns 2D images into multi-colour "filament painting" prints: flat relief plates of stacked translucent layers, printable on single-nozzle printers with filament swaps. — [Snapmaker blog: HueForge 3D printing guide](https://www.snapmaker.com/blog/hueforge-3d-printing/) and [Tom's Hardware how-to](https://www.tomshardware.com/how-to/hugeforge-paint-with-3d-printer) (search snippets only, not opened). HueForge also sells mesh-related modes ("Color Match Mode", "Color Aware Mode") — [HueForge shop: Color Match Mode](https://shop.thehueforge.com/pages/mesh-color-match) (search snippet only; I did not verify whether these apply colour to arbitrary 3D meshes).

**Blender**
- **3MF Import/Export** (Blender Extensions) by **Clonephaze** (maintainer since 2025; originally Ghostkeeper 2020–2023), repo `github.com/Clonephaze/3MF-Blender-Add-on---Maintained`, version 2.7.8, Blender 4.2 LTS+ ("4.2+/5.0+"). ## 4. What practitioners recommend for printing AI-generated figurines in colour; common complaints and fixes

### Takeaway
Before Bambu Studio 2.7 (mid-2026), the consensus was "slicers can't use textures": bake to vertex colours (MeshLab/Blender) or use a converter, then hand-paint in the slicer. Since then, the main complaints are about **import-dialog defaults** (smoothing, PLA matching, auto-mixing, extra filaments), the **32-colour ceiling** for very busy AI textures, and the cost and hit-or-miss quality of AI generation. Reddit threads could not be accessed, so community evidence here comes mainly from the Bambu forum.

### Cited Findings
- Pre-2.7 forum consensus (Dec 2024): "If you're goal is to use the slicer to apply a texture like Blender can, that isn't something the current spate of slicers can do." — [Bambu forum: "Painting model for AMS using existing texture"](https://forum.bambulab.com/t/painting-model-for-ams-using-existing-texture/127034)
- Too many colours: textured AI models contain "literally thousands of texture colors" and hit the "32 color limit". FullSpectrum Studio was built to reduce them. — [Bambu forum: FullSpectrum Studio](https://forum.bambulab.com/t/fullspectrum-studio-automatic-palette-reduction-for-hundreds-of-colors/253789)
- Import-dialog annoyances (2.8.2): forced smoothing, matching to filament types not loaded, unwanted mixes, no saved defaults. One user rolled back to 2.7.1.62, and an answer suggests "skip matching" or another format. — [Bambu forum: "Importing is a mess"](https://forum.bambulab.com/t/importing-is-a-mess/258389)
- Standard 3MF colour dialog adds 10+ filaments even on cancel; workaround is Reload from disk. — [Bambu forum thread](https://forum.bambulab.com/t/how-to-disable-standard-3mf-import-color/241644)
- AI geometry problems that affect colouring: "ai thinks depth is darker colors, not physical dimensions… a hole in a flat surface… ai sees it like a flat wall with a black stain" (i.e., shading/depth baked into texture). Lettering is always jumbled, so add text in the slicer later. A dragon came out with two tails. — [Bambu forum: "Image to 3D Model is really hit or miss" (2025–2026)](https://forum.bambulab.com/t/image-to-3d-model-is-really-hit-or-miss/220515)
- Small-feature colour changes on miniatures: under-extrusion "when there is a color change and a very small segment is printed, such as on the hands or face" (PLA, 0.08 mm layers, 5 cm figure). Advice: re-enable the prime tower ("nozzles don't get properly primed because there is almost no infill" to flush into), dry filament, and consider a 0.2 mm nozzle. Others counter that for 25–50 mm figures resin is easier. — [Bambu forum: "Problems with colored miniatures" (Apr 2025)](https://forum.bambulab.com/t/problems-with-colored-miniatures/160232)
- Vendor-side tip: white filament in AMS setups "may lead to gray discoloration"; print colours separately and assemble — [MakerWorld model page via search](https://makerworld.com/en/models/87836) (search snippet only, not opened).
- Bambu's own guidance: Texture to Color "cuts down on manual color painting"; Gap Area merges small regions; Boundary Smoothness trades sharp vs soft edges. — [Bambu wiki: Texture to Color Painting](https://wiki.bambulab.com/en/software/bambu-studio/texture-to-color)

### Inferences
- The typical practitioner fixes map onto pipeline steps: (a) reduce palette to AMS slot count; (b) merge specks/small islands (Gap Area / PrintPal's 1 mm² rule); (c) avoid shading-as-colour (delight/flatten texture or colour by part); (d) keep the prime tower on for figurines; (e) split the model into parts when colours exceed slots.
- Because Bambu now offers auto-quantisation in the slicer, a custom pipeline is worth keeping mainly for semantic/part-based colouring, shading removal, deterministic palettes matched to owned spools, and PrusaSlicer/Orca compatibility via paint_color.

### Gaps
- **Reddit (r/BambuLab, r/3Dprinting, r/OrcaSlicer, r/prusa3d, r/blender) could not be accessed** (reddit.com returned 403, mirror access was denied, and web search returned no indexed Reddit threads for these queries). No Reddit thread titles or URLs can be cited.

## 5. Practical print constraints that shape colouring decisions

### Takeaway
Waste and time grow with the number of colour changes per layer and the height of the topmost colour change. Dark→light changes need the most flush. 0.2 mm nozzles flush more slowly. Very small painted regions under-extrude or get merged by the slicer. Multi-nozzle machines (H2C/H2D, INDX, XL) cut flush waste by roughly 4× in Bambu's colour-mixing example. Keep the prime tower for figurines, since there is little infill to flush into.

### Cited Findings
- Flushing volume depends mainly on colour pair: "Darker colors need a higher volume flush to switch to lighter colors, and lighter colors need less to switch to darker colors." Flush is extruded at Max Volumetric Speed, so "a **0.2 mm nozzle** may take significantly longer to complete the Flushing step… noticeably increasing filament change time". — [Bambu wiki: Reduce wasting during filament change](https://wiki.bambulab.com/en/software/bambu-studio/reduce-wasting-during-filament-change)
- The prime tower "must be exactly as high as the tallest layer in the print where there is a filament change". Rotating a part so colour changes sit at the bottom cut the tower from 14.76 g to 9.05 g ("about 40% less"). — [Bambu wiki: Reduce wasting during filament change](https://wiki.bambulab.com/en/software/bambu-studio/reduce-wasting-during-filament-change)
- Flush-into-infill/support requires the prime tower to be enabled — [OrcaSlicer/Bambu flush docs via search](https://wiki.bambulab.com/en/software/bambu-studio/parameter/prime-tower) (search snippet only). Micro Center reports >50 % waste reduction from lower flush volumes plus flush-into-infill — [Micro Center article](https://www.microcenter.com/site/mc-news/article/reduce-multifilament-waste.aspx) (search snippet only).
- Multi-nozzle vs single-nozzle: "With four source filaments and about 170 filament changes, a single-nozzle printer uses 130 g of filament, while a multi-nozzle printer uses 35 g in total." Colour mixing should use a multi-nozzle printer. — [Bambu wiki: Color Mixing](https://wiki.bambulab.com/en/bambu-studio/color-mixing)
- Layer height and colour mixing: with Mixed color sublayer on, a 0.4 mm nozzle should use 0.20/0.24 mm presets, and sublayers can drop to 0.02 mm (melt fracture risk). For miniatures, turn sublayers off and use 0.08/0.10/0.12 mm with balanced ratios (1:1, 1:2, 1:1:1). Do not combine variable layer height with mixed sublayers. Mixing works best on near-vertical walls with few slopes, overhangs and curved tops. "Dark colors tend to dominate." — [Bambu wiki: Color Mixing](https://wiki.bambulab.com/en/bambu-studio/color-mixing)
- Thin regions: PrusaSlicer merges non-printable thin painted regions into neighbours (changing colour) and recommends "detect thin walls". Side-wall paint extends inward up to `mmu_segmented_region_max_width`. — [Prusa KB: Multi material painting](https://help.prusa3d.com/article/multi-material-painting_262620)
- Paint depth: OrcaSlicer 2.5 beta adds configurable top/bottom paint penetration layers. — [OrcaSlicer v2.5.0-beta release](https://github.com/OrcaSlicer/OrcaSlicer/releases/tag/v2.5.0-beta)
- Small colour segments on faces/hands under-extrude at colour changes, and keeping the prime tower is advised. A 0.2 mm nozzle is suggested for detail. A related guide suggests 0.08–0.12 mm layers for faces and "features smaller than your nozzle diameter won't print well". — [Bambu forum: Problems with colored miniatures](https://forum.bambulab.com/t/problems-with-colored-miniatures/160232); [Kingroon small parts guide](https://kingroon.com/blogs/3d-printing-guides/how-to-fdm-3d-print-small-parts-with-high-detail-a-step-by-step-tutorial) (search snippet only)
- Plane Cut keeps painting in Bambu Studio 2.7.1+ (minor misalignment near the cut). This makes "split into parts to fit slot count" workflows easier. — [Bambu Studio 2.7.1 release note](https://wiki.bambulab.com/en/software/bambu-studio/release/release-note-2-7-1)
- Colour counts: Bambu Texture-to-Color and 3MF parsing max 32. PrusaSlicer MMU painting max 16 extruders. OrcaSlicer MMU painting >16 is an open PR. Orca limits OBJ colour mapping to the toolhead count on multi-toolhead printers. — sources above ([Bambu T2C](https://wiki.bambulab.com/en/software/bambu-studio/texture-to-color), [Prusa KB](https://help.prusa3d.com/article/multi-material-painting_262620), [Orca PR #13392](https://github.com/OrcaSlicer/OrcaSlicer/pull/13392), [Orca 2.5.0 alpha notes](https://www.orcaslicer.com/wiki/releases/release_2_5_0_alpha))

### Inferences
- Rule-of-thumb minimum colour feature for a 0.4 mm nozzle: about ≥0.4–0.5 mm wide on walls (one extrusion width) and not shorter than a few layers vertically. Below that, expect merging (PrusaSlicer) or under-extrusion/blobbing (forum). A 0.2 mm nozzle roughly halves this, at the cost of slower flushes. This is inferred from the cited sources, not a published spec.
- At 0.08–0.12 mm layers, vertical colour boundaries are quantised to the layer height. Near-horizontal boundaries (e.g., the eye outline on a forward-facing head) show stair-stepping, so pipelines should prefer boundaries that run vertically or follow geometry edges.
- Colour-change count per layer drives waste, so a figurine palette should keep rare colours (eyes, buttons) few and low on the model, or accept a separate part. Bambu's tower-height rule means a single coloured detail near the top (e.g., hair accessory) forces a full-height tower.

- No measured data on flush waste for typical AI figurines (e.g., 4-colour 80 mm figure on A1/X1/H2D) was found.
